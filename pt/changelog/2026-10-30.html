Prévia do Engine 0.5: SDK para download no GitHub Releases, pacotes de jogo menores e uma inicialização que se recupera

Seis compilações de prévia em dois dias, e o SDK estável agora pode ser baixado no GitHub Releases. Os pacotes de jogo ficaram menores, a inicialização espera e se explica em máquinas lentas em vez de desistir, a alternativa WebGL2 está mais estável e a física expõe as configurações do solver.

Prévia do Engine 0.5: SDK para download no GitHub Releases, pacotes de jogo menores e uma inicialização que se recupera

  • Seis compilações de prévia em dois dias, de 0.5.0-dev.15784 a 0.5.0-dev.15789.
  • SDK estável no GitHub Releases: o SDK v0.4.18 e o v0.4.19 estão publicados no repositório público como um arquivo autocontido de SDK para jogos de navegador, com procedência, lista de materiais de software SPDX e somas de verificação SHA-256.
  • Pacotes de jogo menores, e os shaders de materiais são preparados quando são usados pela primeira vez, em vez de todos de antemão.
  • Uma inicialização que se recupera: uma inicialização lenta agora continua esperando e mostra diagnósticos expansíveis em vez de falhar, o carregamento padrão do jogo se recupera de falhas em cache, e o carregamento funciona sob uma política de segurança de conteúdo estrita.
  • Uma alternativa WebGL2 mais estável: a alternativa é escolhida uma única vez, mantém os motivos informados pelos dois backends e preserva corretamente a exposição e os recursos de quadro em dispositivos mais modestos.
  • Física: as iterações do solver agora são configuráveis, o solver usa SIMD, e a detecção contínua de colisão contra mundos de voxels custa cerca de um terço a menos em nosso teste de reprodução.
  • Menos trabalho em quadros estáveis: a preparação do quadro aloca menos memória, a coleta de lixo nos workers diminuiu, relógios de animação inalterados não são mais reescritos, e o ECS ganhou lotes de consulta somente leitura com pouca alocação.
  • Minijogos do WeChat: a cena é renderizada dentro de um orçamento fixo de resolução que pode ser alterado com maxRenderShortSide, enquanto o canvas, a interface e a entrada permanecem em resolução nativa; as compilações para navegador não são afetadas.

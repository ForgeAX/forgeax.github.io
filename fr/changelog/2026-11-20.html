Engine stable v0.5.1, une semaine après v0.5.0 : eau, nuages, empaquetage d’applications et un réglage de lumière demandé par la communauté

Le SDK v0.5.1 est la nouvelle version stable sur GitHub Releases, une semaine après v0.5.0. L’eau, les nuages volumétriques, l’empaquetage pour ordinateur et mobile et l’atelier de profilage sont désormais stables, SpotLight.decay arrive à la demande de la communauté, et les préréglages de qualité choisissent des réglages adaptés à chaque appareil. Quatre versions d’aperçu sont sorties en parallèle.

Engine stable v0.5.1, une semaine après v0.5.0 : eau, nuages, empaquetage d’applications et un réglage de lumière demandé par la communauté

  • Le SDK v0.5.1 est la nouvelle version stable, une semaine après v0.5.0, publiée sur GitHub Releases sous forme d’archive autonome avec provenance, nomenclature logicielle SPDX et sommes de contrôle SHA-256. Quatre versions d’aperçu, de 0.6.0-dev.16826 à 0.6.0-dev.16829, sont sorties pendant ces trois mêmes jours.
  • Nouveautés en stable depuis v0.5.0 : le système d’eau, désormais accompagné d’un exemple de lac à copier dans votre propre projet, les nuages volumétriques précalculés, l’empaquetage Tauri pour ordinateur et mobile, et l’atelier de profilage CPU, mémoire et GPU. Une scène continue de tourner lorsque les nuages ne sont pas disponibles sur un appareil.
  • Demandé par la communauté : SpotLight.decay se comporte désormais comme PointLight.decay, de sorte qu’un projecteur peut garder une luminosité uniforme sur tout son cône. La demande a été faite dans une issue GitHub le 5 novembre et figure dans cette version stable, en natif comme via la couche Three.js. La valeur par défaut de 2 laisse les scènes existantes inchangées.
  • Compatibilité Three.js : @forgeax/engine/three cible désormais Three.js r187 et couvre plus d’une centaine de modules complémentaires, des chargeurs et contrôles aux utilitaires de géométrie, ainsi que les effets de post-traitement et les couleurs de points. Les objets Three.js peuvent aussi partager un World natif, à titre expérimental.
  • Préréglages de qualité et configuration par appareil : un projet déclare quality: { base: { kind: 'device-default' } } pour partir d’une recommandation adaptée à l’appareil, le choix du joueur est enregistré, et app.configuration?.setQuality({ base: { kind: 'preset', preset: 'medium' } }) bascule entre bas, moyen et élevé à l’exécution. Les réflexions en espace écran peuvent être tracées à demi-densité puis reconstruites en pleine résolution.
  • Texte et matériaux : GlyphText gagne worldOriented, pour qu’une étiquette suive son entité au lieu de faire face à la caméra, et peut utiliser une police livrée avec le jeu. Les matériaux découpés qui utilisent alphaCutoff ou alphaHash ont désormais alphaMode: 'opaque' par défaut, ce qui corrige des découpes grises et une image assombrie. L’exposition automatique conserve son historique d’une image à l’autre.
  • Pour les agents d’IA : le SDK fournit une vue d’ensemble des capacités du moteur, et les consignes de démarrage demandent à l’agent de la lire et de planifier avec les fonctions existantes avant d’écrire du code. Le modèle 3D remplace l’échafaudage de tests unitaires par de vraies parties, et forgeax project test réussit pour un jeu sans fichier de test.
  • Dans les versions d’aperçu : les outils du moteur et les libellés de démarrage sont disponibles en chinois et en anglais, avec des README chinois à côté des versions anglaises. Les textures générées sur le GPU à l’exécution couvrent désormais les panoramas et les textures volumiques, et les contours sont préservés avec le MSAA.
  • Également dans les versions d’aperçu : un premier pas vers le streaming de niveaux, où un niveau est préparé en arrière-plan tout en restant masqué puis rejoint la scène en cours, un rendu Deferred plus rapide, et une exposition par défaut neutre dans le modèle 3D.

Engine 0.5 preview: smaller player packages, less repeated rendering work, new diagnostics

Seven preview builds of the 0.5 line went public in three days. Player packages got smaller, the asset budget grew to 4 GiB, rendering repeats less work from frame to frame, and lighting and occlusion bugs found in real game projects were fixed.

Engine 0.5 preview: smaller player packages, less repeated rendering work, new diagnostics

  • Seven preview builds of the 0.5 line, 0.5.0-dev.15088 through 0.5.0-dev.15095, reached the public source in three days.
  • Player packages are smaller: Pack artifacts ship in Asset Bundles that store shared bytes once and use zstd when it saves at least 10%, and large player JSON documents are compressed by default (--compress=false turns this off).
  • Bigger games fit: the asset content budget is now a public option, assetBudgetBytes, with the default raised from 1 GiB to 4 GiB, and a project can now set renderPipelineCapacity in its build options.
  • Rendering repeats less work from frame to frame: scene preparation is carried across frames, particles are planned incrementally, shadow data is retained, and a static shadow cache is available.
  • New building blocks: the Engine Content asset library (ten unit meshes, a checker texture and a default Standard material) mounts through assetLibraries in forge.json, and TimePolicy.fixedCatchUp: 'merged' runs one fixed update when a frame owes several steps.
  • New diagnostics: a WebGPU stub (createApp({ gpuStub })) measures CPU cost without a GPU, and frame events report the real draw cadence and completion latency.
  • Fixed from real game projects: point and spot lights away from the screen centre no longer stop at hard screen-space seams, ambient-occlusion intensity is applied once instead of twice, resting physics bodies cost less, and the npm Engine package is much smaller.

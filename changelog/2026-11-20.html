Engine stable v0.5.1, one week after v0.5.0: water, clouds, app packaging, a community-requested light control

  • SDK v0.5.1 is the new stable release, one week after v0.5.0, published on GitHub Releases as a self-contained archive with provenance, an SPDX software bill of materials and SHA-256 checksums. Four preview builds, 0.6.0-dev.16826 through 0.6.0-dev.16829, shipped in the same three days.
  • New in stable since v0.5.0: the water system, now with a lake example you can copy into your own project, cooked volumetric clouds, native installers for desktop and mobile built through Tauri, and the CPU, memory and GPU profiling workbench. A scene keeps running when clouds are unavailable on a device.
  • Also stable now, including two breaking changes first previewed on 17 November: systems, schedules and resources are identified by the object you define, so a system is registered with world.addSystem(Update, defineSystem({ ... })), and DirectionalLight.staticShadowCache is opt-in (default false). Time scaling with world.acquireTimeScale(scale), release playthroughs with forgeax project play --release and the dev look --view luminance brightness map are in stable too.
  • Requested by the community: SpotLight.decay now matches PointLight.decay, so a spot light can keep an even brightness across its cone. It was asked for in a GitHub issue on 5 November and is in this stable release, natively and through the Three.js layer. The default of 2 keeps existing scenes unchanged.
  • Three.js compatibility: @forgeax/engine/three now targets Three.js r187 and covers more than a hundred add-on modules, from loaders and controls to geometry helpers, plus post effects and point colours. Three.js objects can also share a native World, as an experimental path.
  • Quality presets and device configuration: a project declares quality: { base: { kind: 'device-default' } } to start from a recommendation for the device, a player's choice is saved, and app.configuration?.setQuality({ base: { kind: 'preset', preset: 'medium' } }) switches between low, medium and high at run time. Screen-space reflections can trace at half density and reconstruct at full resolution.
  • Text and materials: GlyphText gains worldOriented, so a label can follow its entity instead of facing the camera, and can use a font shipped with the game. Cutout materials that use alphaCutoff or alphaHash now default to alphaMode: 'opaque', which fixes grey cutouts and a dimmed frame. Automatic exposure keeps its history between frames.
  • For AI agents: the SDK ships an engine capability overview, and the starter guidance tells an agent to read it and plan against existing features before writing code. The 3D starter drops its unit-test scaffolding in favour of real playthroughs, and forgeax project test succeeds for a game that has no test files.
  • Tools: from v0.5.1 the optional View asset workspace ships inside the @forgeax/engine npm package, so a game installed from npm opens it from its root with node ./node_modules/@forgeax/engine/tools/view/start.mjs --project .. Single-HTML packages are now compressed by default; --compress=false restores plain JSON.
  • In the preview builds: engine tools and start-up labels are available in Chinese and English, with Chinese READMEs alongside the English ones. Textures generated on the GPU at run time now cover panoramas and volume textures, and outlines are preserved with MSAA.
  • Also in the preview builds: a first step towards level streaming, where a level is prepared in the background while hidden and then joins the running scene, faster Deferred rendering, and a neutral default exposure in the 3D starter.

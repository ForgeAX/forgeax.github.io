Four preview builds in under a day. Several of these fixes came straight from a game being built on the SDK.

Engine 0.5 preview: smoother effects, an even frame-rate limit, full resolution on 4K displays

  • Four preview builds in under a day, 0.5.0-dev.15780 through 0.5.0-dev.15783.
  • Smoother effects: GPU particle effects now advance on every rendered frame instead of at the fixed simulation rate, so debris, dust and sparks no longer look low-frame-rate in a scene that renders smoothly. A game project reported this, and the fix shipped in the next build.
  • An even frame-rate limit: ExecutionControl.setFrameRateLimit(fps | null) caps the frame rate with steady pacing, so 30 FPS on a 60 Hz display is exactly every second refresh rather than an uneven alternation.
  • The right GPU and the right resolution: WebGPU now asks for the high-performance adapter by default, so dual-GPU laptops run on the discrete GPU, and worker-mode canvases size themselves from the real device limit, so 4K displays no longer render at about half resolution.
  • Much smaller browser builds: ordinary builds now share the compressed asset delivery used by packaged players. In our test game builds the output shrank by about 80% for roughly 2% more build time.
  • More resilient rendering: meshes recover after a GPU device loss, materials that sample a render target stay bound when content is republished, and the pipeline library warms up in a stable order and replays after recovery.
  • Rendering: updated sky and water, sky-only scenes render correctly, opaque materials can opt out of fog with fog: false, and a new withVertexColors geometry helper.
  • Easier to get started: the README was restructured around a showcase, features and a quick start, the effects cookbook is split into topics, the feature lab covers every SDK capability, and the dev overlay shows a subtle game and Engine version label.

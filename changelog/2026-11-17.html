Engine 0.6 preview: water, volumetric clouds, desktop and mobile packaging, a profiling workbench

Four preview builds in two days. A first water system and cooked volumetric clouds arrive, games can be packaged as desktop and mobile apps, a CPU, memory and GPU profiling workbench ships with the engine, and the 3D starter gets automatic exposure and a corrected lower sky.

Engine 0.6 preview: water, volumetric clouds, desktop and mobile packaging, a profiling workbench

  • Four preview builds in two days, 0.6.0-dev.16822 through 0.6.0-dev.16825.
  • Water: a first water system arrives as @forgeax/engine-water, with water bodies and zones, wave-driven surfaces, reflection and underwater views, buoyancy and foam, and a local ripple simulation. Sample scenes run from a harbour to a coastline.
  • Volumetric clouds: cooked cloud layers render through the new VolumetricCloudLayer component, and the tools that cook them are included in the SDK authoring tools.
  • Desktop and mobile packaging: the new forgeax project package --format tauri --platform windows|macos|linux|android|ios builds native installers, and the Tauri project that forgeax project build --target tauri generates from the ordinary browser build now covers Android and iOS as well as desktop. Fixes for Windows and Android followed in the very next build.
  • A profiling workbench ships with the engine: CPU timelines and call trees, memory snapshots and allocation profiles, and GPU resource and timing reports. Each is delivered as an interactive HTML report together with machine-readable data that an AI agent can query.
  • Lighting and image quality: the 3D starter camera now uses automatic exposure, with refreshed clear-day lighting and a paving texture generated on the GPU. The lower part of the sky is rendered correctly, fog works with MSAA, MSAA can be combined with FXAA, and GPU-generated textures become a native asset type.
  • Breaking change in ECS: systems, schedules and resources are now identified by the object you define and import (defineSystem, defineSchedule, defineResource), and their names are only diagnostic labels. Register a system with world.addSystem(Update, defineSystem({ ... })). Also new: world.acquireTimeScale(scale) for slow motion and pause, with Time.unscaledDelta for effects that must keep running.
  • Shadows and builds: DirectionalLight.staticShadowCache is now opt-in (default false) and is no longer invalidated by objects that cast no shadow. devkitAppOptions.canvasPixelRatio accepts 'device' or { mode: 'device', max: 2 }, and production builds reuse cooked materials from the build cache by default.
  • Faster and leaner: meshes keep a single representation at run time, which lowers memory use, material programs that are no longer used are retired, and transform updates for large hierarchies are faster.

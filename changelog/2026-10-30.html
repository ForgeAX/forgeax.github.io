Engine 0.5 preview: SDK downloads on GitHub Releases, smaller game packages, start-up that recovers

Six preview builds in two days, and the stable SDK is now a download on GitHub Releases. Game packages got smaller, start-up waits and explains itself on slow machines instead of giving up, the WebGL2 fallback is steadier, and physics exposes solver settings.

Engine 0.5 preview: SDK downloads on GitHub Releases, smaller game packages, start-up that recovers

  • Six preview builds in two days, 0.5.0-dev.15784 through 0.5.0-dev.15789.
  • Stable SDK on GitHub Releases: SDK v0.4.18 and v0.4.19 are published in the public repository as a self-contained browser game SDK archive, with provenance, an SPDX software bill of materials and SHA-256 checksums.
  • Smaller game packages, and material shaders are prepared when they are first needed rather than all up front.
  • Start-up that recovers: a slow start now keeps waiting and shows diagnostics you can expand instead of failing, default game loading recovers from cached failures, and loading works under a strict Content Security Policy.
  • A steadier WebGL2 fallback: the fallback is chosen once, keeps the reasons both backends reported, and holds its exposure and frame resources correctly on lower-end devices.
  • Physics: solver iteration settings are now configurable, the solver uses SIMD, and continuous collision detection against voxel worlds costs about a third less in our replay benchmark.
  • Less work on steady frames: frame preparation allocates less, worker garbage collection went down, unchanged animation clocks are no longer rewritten, and the ECS gained low-allocation read-only query batches.
  • WeChat Mini Game: the scene renders within a fixed resolution budget that you can change with maxRenderShortSide, while the canvas, UI and input stay at native resolution; browser builds are unaffected.

Engine 0.5 preview: measured loading progress, exact package preview, sturdier agent tooling

Five preview builds in two days. Loading now shows measured progress and records a timeline by default, you can preview the exact bytes a player will download, DevKit live commands are more reliable, and documentation examples that tripped up a real game project were corrected.

Engine 0.5 preview: measured loading progress, exact package preview, sturdier agent tooling

  • Five preview builds in two days, 0.5.0-dev.15096 through 0.5.0-dev.15779.
  • Loading you can measure: the start-up screen shows measured progress that never moves backwards, and a load timeline is on by default, covering worker start, package reads, pipeline creation and the first presented frame, with your own marks through markLoadTimeline.
  • Know what you ship: preview the exact bytes a player will download and inspect Bundle transfers before publishing; WeChat Mini Game packages bundle assets efficiently, with hardened start-up and keyboard focus.
  • Sturdier tooling for AI agents and people: DevKit live commands are more reliable, wait until input is ready and print compact output; SDK documentation examples that failed type-checking in a fresh game project were corrected after a real project ran into them.
  • The View asset preview workspace is now embedded in the SDK as a built-in tool, and the SDK archive leaves out files that only engine contributors need. View's material and UV preview controls with exact triangle picking arrived in the previous build, 0.5.0-dev.15095; mesh geometry can be read back without rendering it.
  • Performance: every frame reports why it stalled along with compile and pipeline counters, worker memory and garbage-collection work went down, optional pipeline libraries warm up in the background, and the render chain's cost now follows what changed rather than the size of the scene.
  • Maintenance: patched HTTP and URI parser vulnerabilities in dependencies, moved the toolchain to npm 12.2.1 and pnpm 12.15.0, and bounded the memory used by zstd decoding.
